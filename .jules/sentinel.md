## 2026-08-09 - Fix SSRF via IPv4-mapped IPv6 literals
**Vulnerability:** The Server-Side Request Forgery (SSRF) protections in `sharpness_tool.py` and `ollama.py` failed to evaluate `is_unspecified` on IPv4-mapped IPv6 addresses (`::ffff:0.0.0.0`). While the protection correctly checked `is_link_local` on both the main object and the mapped object, it only checked `is_unspecified` on the main IP object, allowing bypasses for unspecified addresses using IPv6 formatting.
**Learning:** Python's `ipaddress` module's handling of `ipv4_mapped` attributes requires all security checks (link_local, unspecified) to be explicitly run against the mapped address object in tandem with the main IP address object. Note that loopback addresses must remain allowed in this codebase to support functionality like communicating with local Ollama instances, meaning `is_loopback` should NOT be included in either check list to prevent breaking intended functionality.
**Prevention:** Always mirror the exact set of IP restriction checks (`is_link_local`, `is_unspecified`) on both the main IP object AND the `ipv4_mapped` object (if it exists) to prevent IPv4-mapped IPv6 bypasses without breaking intended access.
